## 1. 技術選型

### 前端
- **純 HTML + CSS + Vanilla JavaScript**
- 理由：需求是一頁式表單，不需要 React/Vue 等框架的複雜度
- CSS 採 **mobile-first** 設計，因為大部分使用者會用手機下單
- 不使用 CSS 框架（如 Bootstrap/Tailwind），手刻即可控制檔案大小與載入速度

### 後端
- **Google Apps Script (GAS)**，部署為 Web App
- 理由：免費、免伺服器、店家可直接在 Google Sheet 管理資料
- GAS Web App 支援 GET/POST，可當作簡易 REST API

### 資料庫
- **Google Sheets**（三張工作表：Products、Orders、Settings）
- 理由：非技術人員可直接在試算表修改商品資訊和查看訂單

### 部署
- **GitHub Pages**（首選）或 **Netlify**
- 理由：靜態檔案，免費託管，支援自訂域名
- 如需自訂域名，兩者都支援 CNAME 設定

## 2. Google Sheet 欄位設計

### Sheet 1：商品資訊（Products）

| 欄位 | 型別 | 說明 |
|------|------|------|
| A: 商品名稱 | 文字 | 芒果品種名稱 |
| B: 五斤價格 | 數字（可留空） | 留空 = 不提供此規格 |
| C: 十斤價格 | 數字（可留空） | 留空 = 不提供此規格 |
| D: 二十斤價格 | 數字（可留空） | 留空 = 不提供此規格 |
| E: 是否售罄 | 文字 | `是` 或 `否` |
| F: 排序 | 數字（選填） | 控制商品在表單中的顯示順序 |
| G: 商品圖片網址 | 文字（選填） | 商品圖片 URL（未來擴充用） |

**範例資料：**

| 商品名稱 | 五斤價格 | 十斤價格 | 二十斤價格 | 是否售罄 | 排序 | 商品圖片網址 |
|---------|---------|---------|----------|---------|------|------------|
| 愛文芒果 | 500 | 900 | 1700 | 否 | 1 | |
| 金煌芒果 | 450 | | 1500 | 否 | 2 | |
| 玉文芒果 | 480 | 880 | 1650 | 是 | 3 | |

- 金煌芒果沒有十斤價格 → 表單不顯示十斤選項
- 玉文芒果已售罄 → 表單中灰掉，無法選購

### Sheet 2：訂單紀錄（Orders）

| 欄位 | 型別 | 說明 |
|------|------|------|
| A: 訂單編號 | 文字 | 格式 `MG-YYYYMMDD-XXXX`（例：`MG-20260413-0001`） |
| B: 訂購時間 | 日期時間 | GAS 伺服器時間，格式 `YYYY-MM-DD HH:mm:ss` |
| C: 姓名 | 文字 | 訂購人姓名 |
| D: 電話 | 文字 | 訂購人電話（用於查詢） |
| E: 住址 | 文字 | 收件地址 |
| F: 備註 | 文字 | 客戶備註 |
| G: 商品 | 文字 | 芒果品種名稱 |
| H: 規格 | 文字 | `五斤` / `十斤` / `二十斤` |
| I: 數量 | 數字 | 訂購箱數 |
| J: 金額 | 數字 | 該品項小計（單價 × 數量） |
| K: 訂單狀態 | 文字 | `待付款` / `已確認` / `已出貨` |

**範例資料（一筆訂單含兩種商品 → 兩列）：**

| 訂單編號 | 訂購時間 | 姓名 | 電話 | 住址 | 備註 | 商品 | 規格 | 數量 | 金額 | 訂單狀態 |
|---------|---------|------|------|------|------|------|------|------|------|---------|
| MG-20260413-0001 | 2026-04-13 14:30:00 | 王小明 | 0912345678 | 台北市信義區... | 希望週末到貨 | 愛文芒果 | 十斤 | 2 | 1800 | 待付款 |
| MG-20260413-0001 | 2026-04-13 14:30:00 | 王小明 | 0912345678 | 台北市信義區... | 希望週末到貨 | 金煌芒果 | 五斤 | 1 | 450 | 待付款 |

> **重點**：王小明同一筆訂單買了兩種芒果，在 Sheet 裡是兩列，共用訂單編號 `MG-20260413-0001`。這樣店家可以針對不同品種分批出貨，各自更新狀態。

### Sheet 3：設定（Settings）

以 key-value 格式儲存，A 欄為鍵、B 欄為值：

| 鍵 | 值 | 說明 |
|------|------|------|
| 匯款銀行 | 台灣銀行 | 銀行名稱 |
| 分行 | 屏東分行 | 分行名稱 |
| 帳號 | 012-345678-901234 | 匯款帳號 |
| 戶名 | 王大芒 | 匯款戶名 |
| 公告訊息 | 今年產季預計 6 月開始出貨 | 顯示在表單頂部的公告（留空則不顯示） |
| 匯款期限說明 | 請於下單後三日內完成匯款 | 顯示在匯款資訊區塊 |

> 把匯款資訊和公告放在 Sheet 裡，店家可以直接改試算表，不用動程式碼。

## 3. Google Apps Script API 設計

### 部署方式
1. 在 Google Sheet 中開啟「擴充功能 → Apps Script」
2. 撰寫 `Code.gs`
3. 部署 → 新增部署 → 網頁應用程式
4. 執行身分：**我自己**
5. 存取權限：**任何人**

### API Endpoints

GAS Web App 只有一個 URL，透過 query parameter 區分動作。

---

#### 3.1 GET — 取得商品列表與設定

```
GET {WEB_APP_URL}?action=products
```

**Response（JSON）：**
```json
{
  "success": true,
  "data": {
    "products": [
      {
        "name": "愛文芒果",
        "prices": {
          "five": 500,
          "ten": 900,
          "twenty": 1700
        },
        "soldOut": false
      },
      {
        "name": "金煌芒果",
        "prices": {
          "five": 450,
          "ten": null,
          "twenty": 1500
        },
        "soldOut": false
      },
      {
        "name": "玉文芒果",
        "prices": {
          "five": 480,
          "ten": 880,
          "twenty": 1650
        },
        "soldOut": true
      }
    ],
    "settings": {
      "bankName": "台灣銀行",
      "bankBranch": "屏東分行",
      "accountNumber": "012-345678-901234",
      "accountHolder": "王大芒",
      "announcement": "今年產季預計 6 月開始出貨",
      "paymentNote": "請於下單後三日內完成匯款"
    }
  }
}
```

**設計決策：**
- `prices` 中值為 `null` 的規格 → 前端不顯示該規格
- 售罄商品仍回傳（`soldOut: true`） → 前端灰掉顯示，讓客人知道有這個品種
- `settings` 隨商品一起回傳，減少一次請求

---

#### 3.2 GET — 查詢訂單

```
GET {WEB_APP_URL}?action=query&phone=0912345678
```

**Response（JSON）：**
```json
{
  "success": true,
  "data": {
    "orders": [
      {
        "orderId": "MG-20260413-0001",
        "orderTime": "2026-04-13 14:30:00",
        "name": "王小明",
        "address": "台北市信義區...",
        "note": "希望週末到貨",
        "items": [
          {
            "product": "愛文芒果",
            "spec": "十斤",
            "quantity": 2,
            "amount": 1800,
            "status": "已確認"
          },
          {
            "product": "金煌芒果",
            "spec": "五斤",
            "quantity": 1,
            "amount": 450,
            "status": "待付款"
          }
        ],
        "totalAmount": 2250
      }
    ]
  }
}
```

**設計決策：**
- 回傳時把同一訂單編號的品項 **group 起來**，前端比較好顯示
- 每個 item 有獨立的 `status`，因為不同品種可能分批出貨
- Sheet 裡仍然是分列儲存

---

#### 3.3 POST — 提交訂單

```
POST {WEB_APP_URL}?action=order
Content-Type: application/json
```

**Request Body：**
```json
{
  "name": "王小明",
  "phone": "0912345678",
  "address": "台北市信義區松仁路100號",
  "note": "希望週末到貨",
  "items": [
    {
      "product": "愛文芒果",
      "spec": "ten",
      "quantity": 2
    },
    {
      "product": "金煌芒果",
      "spec": "five",
      "quantity": 1
    }
  ]
}
```

**Response（JSON）：**
```json
{
  "success": true,
  "data": {
    "orderId": "MG-20260413-0001",
    "totalAmount": 2250,
    "message": "訂單已送出，請於三日內完成匯款"
  }
}
```

**伺服器端處理邏輯：**
1. 驗證必填欄位（name、phone、address、items 非空）
2. 驗證 items 中的商品名稱和規格是否存在於 Products sheet
3. 檢查商品是否售罄
4. 從 Products sheet 查詢價格，**在伺服器端計算金額**（不信任前端傳來的金額）
5. 產生訂單編號（`MG-YYYYMMDD-XXXX`，XXXX 為當日流水號）
6. 每個 item 寫入 Orders sheet 一列（共用訂單編號、姓名、電話等）
7. 所有新訂單狀態預設為 `待付款`
8. 回傳訂單編號和總金額

---

#### 3.4 錯誤回應格式

```json
{
  "success": false,
  "error": "錯誤訊息（例：找不到該電話的訂單紀錄）"
}
```

常見錯誤情境：
- 必填欄位缺失
- 商品名稱不存在
- 商品已售罄
- 規格不存在或該規格無價格
- 電話查無訂單

### 4.5 Loading 與錯誤狀態

- **頁面初始載入**：商品區域顯示 skeleton loading（灰色區塊閃爍）
- **送出訂單中**：按鈕顯示 spinner + 文字「送出中...」，禁用按鈕防重複提交
- **查詢中**：查詢按鈕同上
- **API 錯誤**：顯示紅色提示訊息於對應區塊上方
- **網路錯誤**：顯示「無法連線，請檢查網路後重試」

### 4.6 手機版注意事項

- **Mobile-first CSS**：預設為手機版面，`@media (min-width: 768px)` 擴展桌面版
- 商品卡片**全寬堆疊**，不做多欄排列
- 數量 input 用 `type="number"` + `inputmode="numeric"`，手機彈數字鍵盤
- 電話欄位用 `type="tel"`，手機彈電話鍵盤
- 按鈕大小至少 **44px** 高度（Apple HIG 建議的最小觸控尺寸）
- 表單送出時加 loading 動畫，防止重複點擊
- 訂單摘要區塊用 `position: sticky` 黏在底部（桌面版可改為側欄）

## 5. 開發步驟

### Phase 1：後端（Google Sheet + Apps Script）
1. 建立 Google Sheet，設定 Products、Orders、Settings 三張工作表的欄位標題
2. 在 Products 填入測試商品資料（至少 3 種芒果，含一種售罄、一種缺少某規格）
3. 在 Settings 填入匯款資訊和測試公告
4. 撰寫 `Code.gs`：
   - `doGet(e)` 處理 GET 請求，根據 `e.parameter.action` 分流
   - `doPost(e)` 處理 POST 請求
   - `getProducts()` 讀取 Products + Settings sheet
   - `queryOrders(phone)` 查詢訂單並 group by 訂單編號
   - `createOrder(data)` 驗證 + 計算金額 + 寫入 + 回傳
   - `generateOrderId()` 產生當日流水號
5. 部署為 Web App，用 curl 或瀏覽器測試三個 endpoint

### Phase 2：前端 — 訂購表單
6. 建立 `index.html` 基本結構（tab、表單骨架、語意化 HTML）
7. 撰寫 `css/style.css`（mobile-first RWD）
8. 撰寫 `js/app.js`：
   - 頁面載入時呼叫 `?action=products`，動態生成商品卡片
   - 渲染匯款資訊和公告
   - 實作勾選規格 → 顯示數量欄位 → 即時計算小計和總額
   - 實作表單驗證（必填檢查、電話格式、至少選一項商品）
   - 實作送出訂單（POST → loading → 成功/失敗畫面）

### Phase 3：前端 — 查詢功能
9. 撰寫 `js/query.js`：
   - 輸入電話 → 呼叫 `?action=query`
   - 渲染訂單列表（分組顯示、狀態標籤）
   - 無訂單時顯示友善提示

### Phase 4：收尾
10. 整體測試：
    - 手機瀏覽器實測（iOS Safari + Android Chrome）
    - 多商品同時訂購 → 確認 Sheet 分列
    - 售罄商品顯示正確
    - 空規格隱藏正確
    - 查詢功能正常
11. 部署到 GitHub Pages / Netlify
12. 更新 README 中的 Web App URL 設定說明

## 7. 額外建議欄位

以下欄位不在原始需求中，但建議考慮加入：

### 建議優先加入（低成本、高效益）

| 欄位 | 位置 | 理由 |
|------|------|------|
| **Email（選填）** | 訂購表單 | 未來可用 GAS 的 MailApp 自動寄出貨通知信。不設必填，因為有些長輩不用 email |
| **匯款帳號末五碼（選填）** | 訂購表單或查詢頁補填 | 方便店家核對匯款，大幅加速對帳流程 |
| **希望到貨時段（選填下拉）** | 訂購表單 | 選項：不指定 / 上午 / 下午。宅配可指定時段，改善顧客體驗 |

### 視需求加入

| 欄位 | 位置 | 理由 |
|------|------|------|
| 運費 | Settings sheet | 若需加收運費，可在設定中配置金額或免運門檻。目前假設含運 |

## 8. 注意事項與限制

### Google Apps Script 限制
- **每日觸發次數**：免費 Google 帳號每日 20,000 次呼叫，一般小型訂購足夠
- **單次執行時間**：上限 6 分鐘，簡單讀寫不會超過
- **併發**：GAS 不擅長處理高併發，但芒果訂購不會有秒殺等級流量
- **CORS**：GAS Web App 部署後會回傳 redirect（302 → 200），前端用 `fetch(url, { redirect: 'follow' })` 即可正常取得 JSON 回應

### 安全考量
- **不信任前端金額**：金額一律在 GAS 端根據 Products sheet 重新計算
- **電話查詢隱私**：任何人輸入電話都能查到訂單，這是簡化設計的取捨。如需更高安全性，可加一個「查詢密碼」欄位（下單時自設 4 位數字）
- **XSS 防護**：前端渲染 GAS 回傳資料時，使用 `textContent` 而非 `innerHTML`
- **輸入驗證**：前端做基本格式檢查（UX），GAS 端做實際驗證（安全）

### 使用者體驗
- 商品載入中顯示 skeleton / loading 狀態，避免空白閃爍
- 送出訂單時按鈕顯示 loading + 禁用，防止重複提交
- 表單驗證即時回饋（欄位失焦時檢查，不要等到按送出才報錯）
- 考慮用 `localStorage` 暫存姓名/電話/地址，方便回購客戶不用重填
- 訂單摘要隨勾選即時更新，讓客人清楚知道目前選了什麼
