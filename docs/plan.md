# 芒果訂購網站 — 技術規劃文件

## 1. 技術選型

| 層級 | 技術 | 說明 |
|------|------|------|
| 前端 | HTML + CSS + Vanilla JS | 一頁式靜態網站，無需框架，部署簡單 |
| 樣式 | Tailwind CSS（CDN） | 快速開發響應式 UI，無需建置工具 |
| 後端 API | Google Apps Script（Web App） | 免費、免伺服器、直接存取 Google Sheets |
| 資料庫 | Google Sheets | 兩個工作表：商品、訂單 |
| 部署 | GitHub Pages 或 Netlify | 靜態檔案託管，免費 |

**為什麼不用框架？** 此專案為單頁表單，邏輯單純，Vanilla JS 足夠且載入最快。若未來需求增長再考慮遷移。

## 2. Google Sheets 欄位設計

### Sheet 1：商品（Products）

| 欄位 | 型別 | 說明 |
|------|------|------|
| 名稱 | 文字 | 商品名稱 |
| 五斤價格 | 數字 | 留空表示不提供此規格 |
| 十斤價格 | 數字 | 留空表示不提供此規格 |
| 二十斤價格 | 數字 | 留空表示不提供此規格 |
| 是否售罄 | 布林 | TRUE = 售罄，不顯示於前端 |

**範例資料：**

| 名稱 | 五斤價格 | 十斤價格 | 二十斤價格 | 是否售罄 |
|------|---------|---------|-----------|---------|
| 愛文芒果 | 450 | 850 | 1600 | FALSE |
| 金煌芒果 | | 750 | 1400 | FALSE |
| 玉文芒果 | 500 | 950 | | FALSE |
| 土芒果 | 350 | 650 | 1200 | TRUE |

> 金煌芒果沒有五斤規格（留空），前端不會顯示該選項。
> 土芒果已售罄，前端不會顯示此商品。

### Sheet 2：訂單（Orders）

| 欄位 | 型別 | 說明 |
|------|------|------|
| 訂單編號 | 文字 | 格式 `MG-YYYYMMDD-XXXX`，同一筆訂單多商品共用編號 |
| 時間 | 日期時間 | 提交時間 |
| 姓名 | 文字 | 收件人 |
| 電話 | 文字 | 收件人電話，也作為查詢依據 |
| 住址 | 文字 | 收件地址 |
| 備註 | 文字 | 顧客備註 |
| 商品 | 文字 | 商品名稱 |
| 規格 | 文字 | 五斤 / 十斤 / 二十斤 |
| 數量 | 數字 | 該商品該規格的數量 |
| 金額 | 數字 | 單價 × 數量 |
| 狀態 | 文字 | 待付款 / 已確認 / 已出貨 |

**範例資料（一筆訂單含兩項商品）：**

| 訂單編號 | 時間 | 姓名 | 電話 | 住址 | 備註 | 商品 | 規格 | 數量 | 金額 | 狀態 |
|---------|------|------|------|------|------|------|------|------|------|------|
| MG-20260413-0001 | 2026/04/13 14:30 | 王小明 | 0912345678 | 台北市大安區... | 希望週五到 | 愛文芒果 | 十斤 | 2 | 1700 | 待付款 |
| MG-20260413-0001 | 2026/04/13 14:30 | 王小明 | 0912345678 | 台北市大安區... | 希望週五到 | 金煌芒果 | 二十斤 | 1 | 1400 | 待付款 |

> 同一筆訂單的多個商品分列儲存，共用訂單編號 `MG-20260413-0001`。

## 3. API 設計（Google Apps Script Web App）

所有端點透過同一個 Web App URL，以參數區分操作。

### GET — 取得商品列表

```
GET ?action=products
```

**回應：**
```json
{
  "success": true,
  "data": [
    {
      "name": "愛文芒果",
      "prices": { "5": 450, "10": 850, "20": 1600 },
      "soldOut": false
    },
    {
      "name": "金煌芒果",
      "prices": { "10": 750, "20": 1400 },
      "soldOut": false
    }
  ]
}
```

> 已售罄商品不回傳。沒有價格的規格不出現在 `prices` 物件中。

### GET — 查詢訂單（以電話號碼）

```
GET ?action=query&phone=0912345678
```

**回應：**
```json
{
  "success": true,
  "data": [
    {
      "orderId": "MG-20260413-0001",
      "time": "2026/04/13 14:30",
      "name": "王小明",
      "status": "待付款",
      "items": [
        { "product": "愛文芒果", "spec": "十斤", "qty": 2, "amount": 1700 },
        { "product": "金煌芒果", "spec": "二十斤", "qty": 1, "amount": 1400 }
      ],
      "total": 3100
    }
  ]
}
```

### POST — 提交訂單

```
POST (JSON body)
```

**請求：**
```json
{
  "action": "order",
  "name": "王小明",
  "phone": "0912345678",
  "address": "台北市大安區...",
  "note": "希望週五到",
  "items": [
    { "product": "愛文芒果", "spec": "10", "qty": 2 },
    { "product": "金煌芒果", "spec": "20", "qty": 1 }
  ]
}
```

**回應：**
```json
{
  "success": true,
  "orderId": "MG-20260413-0001",
  "total": 3100
}
```

> 金額由 Apps Script 端根據 Sheet 當前價格計算，不信任前端傳入的金額。

### UI 要點

- 響應式設計，手機優先（顧客多用手機訂購）
- 商品卡片從 API 動態生成，無價格的規格不顯示
- 數量欄位預設隱藏，勾選規格後才出現
- 總額即時計算，隨選擇變動
- 送出前驗證必填欄位（姓名、電話、住址、至少選一項商品）
- 送出後顯示訂單編號與匯款提醒

## 5. 開發步驟

| 步驟 | 內容 |
|------|------|
| 1 | 建立 Google Sheet，設定商品表與訂單表結構，填入測試資料 |
| 2 | 撰寫 Apps Script：GET products（讀取商品、過濾售罄、整理價格） |
| 3 | 撰寫 Apps Script：POST order（驗證資料、計算金額、寫入訂單表、回傳訂單編號） |
| 4 | 撰寫 Apps Script：GET query（以電話查詢、彙整同訂單編號的品項） |
| 5 | 部署 Apps Script 為 Web App，測試三個 API |
| 6 | 開發前端：HTML 結構 + Tailwind 樣式 + 響應式佈局 |
| 7 | 開發前端：串接商品 API，動態渲染商品卡片 |
| 8 | 開發前端：表單邏輯（規格勾選、數量輸入、總額計算、驗證） |
| 9 | 開發前端：串接送出訂單 API，處理成功/失敗回饋 |
| 10 | 開發前端：訂單查詢頁，串接查詢 API |
| 11 | 整體測試（下單流程、查詢流程、手機測試、邊界狀況） |
| 12 | 部署前端至 GitHub Pages 或 Netlify |

## 7. 額外欄位建議

| 欄位 | 建議 | 理由 |
|------|------|------|
| Email | **建議加入（選填）** | 可寄送訂單確認信、出貨通知，用 Apps Script 的 MailApp 即可實現，成本極低 |
| 送貨時段 | **建議加入（選填）** | 芒果怕曬，顧客可能偏好特定時段收貨。可設選項：不指定 / 上午 / 下午 |
| 收件人（與訂購人不同） | 視需求 | 若有送禮場景可加，否則增加表單複雜度 |
| 發票 / 統編 | 視需求 | 小農直售通常不需要，若有公司客戶再加 |
| 匯款後五碼 | **建議加入** | 方便賣家對帳確認，可在查詢頁讓顧客補填，或在表單加一個選填欄位 |

### 建議優先加入的欄位

1. **Email（選填）** — 實作成本低，後續可自動寄通知
2. **匯款後五碼（選填）** — 加速對帳流程
3. **送貨時段（選填）** — 改善顧客體驗

這三個欄位都設為選填，不影響表單填寫速度，但能明顯提升營運效率與顧客體驗。
